## 一、经验库是什么

朴素地讲，同一个坑踩第一次可以理解，踩到第一百次纯属烧 Token。经验库做的事情，就是让后台算法自动扫描 Agent 的历史运行轨迹，提炼出共性的**成功走通路径**和**失败避坑教训**（图 1），尤其擅长覆盖工具调用参数、执行路径绕远、延时瓶颈这类不依赖具体行业的通用痛点——然后通过上下文注入喂给后续请求，让 Agent 越跑越熟。

*图 1：经验库机制：从运行轨迹自动挖掘经验，经 Skill 召回后注入 Agent 上下文*

## 三、四步把经验库接进 Agent（千万别漏权限坑）

要让在线跑着的 Agent 真正用上这几条经验，只需要装一个经验召回 Skill，让它在运行时去经验库捞最相关的经验塞进上下文：

1. **创建 API Key**：作为 Agent 侧查询经验库的访问凭证；
2. **安装 Skill**：进入 Agent 所在目录，安装 `alibabacloud-agentloop-experience`（图 4）；

![AgentLoop 数据飞轮实践（五）配图 4](../../assets/imgs/chapter-18/image-066.png)

*图 4：安装 alibabacloud-agentloop-experience Skill*

3. **写入 env 配置**：把目标经验库标识配进环境变量，告诉 Skill 去哪查；
4. **放开三项权限（最容易卡住的一步）**：把该 Skill 加进 Agent **白名单**、打开 **Shell 权限**（因为经验召回底层会调一条 shell 命令）、并且在新建会话时配置 **`allow shell`**（图 5）。这三项缺任何一个，Skill 都会悄悄哑火。

![AgentLoop 数据飞轮实践（五）配图 5](../../assets/imgs/chapter-18/image-067.png)

*图 5：打开 Shell 权限并 allow shell*

## 四、消融实验：怎么注入才不帮倒忙？

千万别看到演示少走了几步就直接全量上线！经验不是塞进提示词就一定有用——召回太松会灌进一堆噪声，塞太多条会稀释模型对当前用户问题的注意力，语气写太死甚至会让模型死搬过期经验。

为了严格验证每一项策略是不是真的正向收益，演示以 **「完全不注入经验」作为基线**，跑了一轮逐因素拆开的消融实验（图 8），把五个注入旋钮调到了最佳档位：

![AgentLoop 数据飞轮实践（五）配图 8](../../assets/imgs/chapter-18/image-070.png)

*图 8：消融实验：召回阈值、注入条数等策略对比*

- **召回阈值选 0.6**：相似度 1 为完全一致、0 为毫不相干；设太高经常召不出来，设太低乱七八糟的经验全混进来，实测 0.6 是信噪比最稳的水位；
- **每次只喂 top1**：只取最相似的那 1 条经验，贪多反而占光上下文窗口、分散注意力；
- **摆对上下文顺序**：实测最吃得进的排布顺序是——**用户真实问题 → 业务经验使用规则 → top1 经验**；
- **给经验瘦身**：把原始经验里带出来的具体场景啰嗦细节全删掉，只留标题摘要、适用条件和关键结论，并卡死字符上限；
- **加上防护护栏**：明确叮嘱模型「以下经验仅作历史参考，与当前事实不符时不得照搬」，给模型留足不盲从的判断余地。

五篇文章走完，整条闭环首尾扣合（图 10）：

![AgentLoop 数据飞轮实践（五）配图 10](../../assets/imgs/chapter-18/image-072.png)

*图 10：数据飞轮完整一圈：接入 → 观测/审计 → 评估 → 数据集 → 实验回测 → 经验库 → 反哺 Agent*

- **人工专家驱动（第 2~4 篇）**：把领域专家的隐性直觉固化为黄金指标与题目级 Rubric，在线评估捞出 Badcase，离线内网实验台拿硬分数验真后再改上线；
- **全自动进化（本篇）**：后台算法自动从历史轨迹提炼通用经验，装一个 Skill 随用随取，再用消融实验兜住「绝不帮倒忙」的底线。

说到底，飞轮五个环节就干五件事：接入回答「刚才发生了什么」，观测回答「细节卡在哪一步」，评估回答「到底办得好不好」，实验回答「这版改动到底有没有用」，经验库回答「怎样不用人盯也能越跑越顺」。Agent 上线从来不是结项，而是这只飞轮转起第一圈的发令枪。
