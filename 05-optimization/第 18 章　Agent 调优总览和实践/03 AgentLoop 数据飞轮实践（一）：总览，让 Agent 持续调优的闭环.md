Agent 上线只是起点。真正决定一个 Agent 值不值得长期用的，是上线之后能不能 **持续调优**：用户吐槽的问题能不能系统性地抓出来、存进题库、修好并验证有效，让系统跑一圈比一圈稳。

大多数团队卡在这里的原因很简单：没跑通之前手头全是零散的「看几条抱怨、顺手改两句 Prompt」——既不可复现，改完也答不上来「这次到底变好了多少，有没有把别的题改坏」。本系列基于一次约 64 分钟的完整实操演示（从新建工作空间一路做到消融实验出账单），带你把数据飞轮从头转到底。第一篇先立全景，后四篇逐步拆实操细节。

## 二、AgentLoop 的核心定位：把七个环节咬合成飞轮

开发期靠几十道固定测试题和研发直觉还能凑合，一旦上线面对发散的真实用户提问，团队需要的不再是零敲碎打的人肉改 Prompt，而是一套覆盖运行、发现、验证到沉淀的持续闭环。图 2 展示了平台入口，图 3 串起了完整的七步飞轮路径：

![AgentLoop 数据飞轮实践（一）配图 2](../../assets/imgs/chapter-18/image-021.png)

*图 2：接入、观测、审计、数据集、评估、实验等功能入口（视频 01:20）*

1. **数据接入**：把 Agent 每次运行的 Trace 数据接进来——这是地基，没数后面全空转；
2. **观测**：顺着 Trace 看清 Agent 每一轮调了什么模型、用了哪些工具、卡在哪个分支；
3. **审计**：对运行过程做安全与合规视角检查；
4. **数据集**：把抓出来的 Badcase（答偏、绕远、报错）存成飞轮的「弹药库」，专供后面实验反复回测；
5. **评估**：建评估任务，同时从 **结果**（答得对不对）和 **过程**（工具选得合不合理、路径绕没绕弯）两头打分；
6. **实验**：挑出低分题建实验计划反复回测，改一版跑一轮，看清总分和单题分到底涨了还是跌了；
7. **经验库**：后台算法自动从历史轨迹里提炼通用避坑经验并反哺给 Agent——这是整套飞轮里唯一不需要人类专家手写标准的自动化环节。

![AgentLoop 数据飞轮实践（一）配图 3](../../assets/imgs/chapter-18/image-022.png)

*图 3：数据飞轮全景：接入 → 观测 → 审计 → 数据集 → 评估 → 实验 → 经验库，经验再反哺 Agent（示意图，依据演示内容整理）*

飞轮真正的威力不在某一个功能有多炫，而在 **首尾相接**：观测抓出的问题进数据集，评估定下的标尺拿去做实验，实验筛出的方案上线后又产出一批更干净的新轨迹，继续喂给下一轮评估和经验挖掘。

## 三、两种调优模式：人工立规矩 vs 自动攒经验

围绕这套能力，飞轮提供了两条互补的调优路线（图 4）：一条像「人开车」，靠懂业务的人定标准；一条像「自动驾驶」，靠算法从通用规律里自己攒经验。

![AgentLoop 数据飞轮实践（一）配图 4](../../assets/imgs/chapter-18/image-023.png)

*图 4：两种调优模式：人类专家驱动的手工闭环 vs 经验库全自动化（示意图，依据演示内容整理）*

### 模式一：人类专家驱动（立业务底线）

金融、医疗或企业内部客服里「什么回答才算合格」没有通用套路，必须靠懂业务的人给出行业判断：先由专家把脑子里「这句答得好、那步漏了关键确认」的隐性标准写成显性的 Rubric，再通过在线评估把线上 Badcase 捞进数据集，然后改一版 Prompt 或 Skill 跑一轮实验回测，看清分数变化后再继续针对性调优。这个闭环的核心产出不只是修好几条错题，而是把专家的经验固化成团队长期复用的验收题库和评分细则。

### 模式二：全自动化经验库（做通用增益）

另一条路不需要专家逐条写规则：任何 Agent 都会碰到工具调用参数易错、路径绕弯试错、延迟偏高等通用共性问题。开启经验库后，平台直接从历史运行轨迹里自动挖出成功和失败经验，在 Agent 里装上一个经验召回 Skill 就能随用随取。不过真上生产前别盲信，务必跑一遍消融实验——看看注入几条经验、放上下文哪个位置、加什么防护护栏才真正带来正向收益，这正是本系列第 5 篇要重点演示的内容。

两条路并非二选一：模式一立住业务质量底线，模式二在底线之上自动降耗提速。
