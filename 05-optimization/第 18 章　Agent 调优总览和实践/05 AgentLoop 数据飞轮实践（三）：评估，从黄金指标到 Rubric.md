数据接进来之后，马上要回答一个最头疼的问题：**Agent 到底跑得怎么样？**

Agent 的回答是开放文本，人工抽检几条又慢又贵，还变不成可复用的尺子。本篇跟着演示里的客服 Agent，从头走完「定黄金指标 → 拆 Rubric → 建评估器 → 跑评估任务 → 沉淀 Badcase」整条评估链路，把模糊的「好像不太行」变成带分档、带权重、带证据依据的可追溯分数。

## 一、先分清两层结构：评估器 vs 评估任务

平台把评估拆成两层，类似「考卷」和「组织一场考试」的关系：

1. **评估器（Evaluator）**：相当于考卷和评分标准——定义要评什么指标、用什么类型去评、输入输出变量长什么样、具体怎么打分（Rubric）。它跟具体数据解耦，建好之后能反复复用。
2. **评估任务（Evaluation Task）**：相当于安排一场具体考试——挑定哪份数据、什么时候触发跑、抽多少样本、挂上哪几个评估器来考。

其中评估器有一个关键开关——用 **Agent** 评还是用 **Code** 评（图 1）：

![AgentLoop 数据飞轮实践（三）配图 1](../../assets/imgs/chapter-18/image-035.png)

![AgentLoop 数据飞轮实践（三）配图 2](../../assets/imgs/chapter-18/image-036.png)

*图 1：评估器类型：Agent 评估或 Code 评估（视频 14:28）*

- **Code 评估**：写确定性代码规则（判 JSON 格式、字符长度、字段齐全度），便宜飞快，但写不出语义判断；
- **Agent 评估**：派一个专职评估 Agent 阅读输入、输出和执行轨迹，对照 Rubric 像阅卷老师一样打分。它能读懂「回答是否切题」「步骤有没有绕远」，演示里选的就是 Custom Agent 模式；代价是每评一条都要耗模型资源，所以后面必须配采样控制成本。

## 二、定义黄金指标：让 AI 帮忙拆成 Rubric

建评估器之前，先回答：**在这个业务里，什么才算「好」？**

客服场景主要盯两块黄金指标：**回答质量**（答案准不准、全不全）和 **执行过程**（工具用得合不合理、有没有绕远）。光看结果容易放过「瞎猫碰上死耗子」，光看过程容易放过「步骤规矩但答非所问」，两头都得评。

写黄金指标不用憋着从零硬写，演示里直接把业务要求丢给 AI 帮拆解，Prompt 核心意思很直白：

> 请制定黄金指标，用来评判客服 Agent 的回答质量和执行过程，并对黄金指标进行拆解，定义成 Rubric——每个指标在什么情况下打什么分数，每个指标有权重，最终汇总成一个加权分数。

AI 吐出来的清单直接就能用（图 2）：涵盖回答质量与执行过程两大类、每一项具体的分档给分规则、各自权重、总分算式，甚至还贴心补上了「加权诊断分 + 硬门禁 + 证据覆盖率」的实操建议。

![AgentLoop 数据飞轮实践（三）配图 3](../../assets/imgs/chapter-18/image-037.png)

*图 2：AI 的输出：黄金指标拆解成 Rubric——评分标准、分档、权重、总分公式（视频 18:45）*

这就是 **Rubric** 的精髓：把抽象的「答得好」拆成一个个可落判的分档细则和权重。另外两条一线经验很实用：对业务极熟时人工自己定更稳；如果特别忌惮某一条红线（比如客服不能泄露用户隐私），干脆把它单独拎出来建成一个顶层评估器单看，别让它被淹没在加权总分里。

## 三、创建评估器

拿到 Rubric 后，就可以进控制台新建类型为 Custom Agent 的评估器了（图 3）——本地装了 AgentLoop 的 Skill 时也能让 Skill 辅助生成整套定义。

![AgentLoop 数据飞轮实践（三）配图 4](../../assets/imgs/chapter-18/image-038.png)

![AgentLoop 数据飞轮实践（三）配图 5](../../assets/imgs/chapter-18/image-039.png)

*图 3：创建评估器，类型选 Custom Agent（视频 21:33）*

Rubric 就直接填进评估器的 Prompt 输入区里（图 4），同时把要读的三个输入变量放进去：用户输入 `input`、Agent 最终答复 `output`，以及完整执行轨迹（`agent_trajectory` / `trace.agent`）。填的时候顺手做做减法——把模板里用不上的人工反馈等冗余字段删掉，保留的资产越干净，后面越好维护。另外如果团队沉淀了客服领域知识 Skill，还可以直接挂到这个评估器上，等于给阅卷老师发了本业务手册。

![AgentLoop 数据飞轮实践（三）配图 6](../../assets/imgs/chapter-18/image-040.png)

*图 4：评估器的定义：Rubric 评分细则写在 Prompt 输入区里（视频 22:15）*

输出格式必须定义为结构化 Schema（图 5），让评估器每次打分都乖乖交出一套可检索、可解释的字段：

![AgentLoop 数据飞轮实践（三）配图 7](../../assets/imgs/chapter-18/image-041.png)

![AgentLoop 数据飞轮实践（三）配图 8](../../assets/imgs/chapter-18/image-042.png)

*图 5：输出定义：score / raw-weighted score / final score 等（视频 23:08）*

- `score`：单项得分；
- `raw-weighted score` 与 `final score`：浮点数（权重 0~100 折算、最终归一化到 0~1 区间）；
- `decision`、`scenario type`（枚举）：结论分类和场景标签，方便下游一键筛出所有不合格记录；
- `summary`、`explanation`：文字摘要与扣分理由——**只有分数没有解释，低分记录就不知道该改哪**；
- `rubric version`：Rubric 版本号。标准本身会迭代，留好版本号才能分清分数波动到底是 Agent 改好了还是尺子放宽了。

## 四、创建评估任务：挑对数据源、策略、采样与映射

考卷备好，接下来创建评估任务开考，重点配对四个选项：

### 1. 选「轨迹数据」还是「Trace 数据」？

平台里有两份数据（图 6）：**Trace 数据**偏微服务调用链视角（哪个服务调了哪个服务、耗时几毫秒）；**轨迹（Trajectory）数据**才是还原 Agent 思考、提示词和工具交互步骤的行为视角。评回答质量和过程好坏，果断选 **轨迹数据**。

![AgentLoop 数据飞轮实践（三）配图 9](../../assets/imgs/chapter-18/image-043.png)

![AgentLoop 数据飞轮实践（三）配图 10](../../assets/imgs/chapter-18/image-044.png)

*图 6：轨迹数据：Agent 思考与工具调用过程*

### 2. 选运行策略

- **持续评估**：按分钟盯盘，来一条新数据就评一条，专用来及时抓线上 Badcase；
- **历史评估**：对过去几小时存量跑一次收工，适合专项复盘。

### 3. 配采样控制（防烧钱的关键开关）

因为用评估 Agent 逐条打分成本不低，跑通验证期完全不用全量上。演示里把最大样本数限成 100 条（采样比例 100%，即最多评 100 条，图 7），先把闭环跑稳，确认有价值再按需放开。

![AgentLoop 数据飞轮实践（三）配图 11](../../assets/imgs/chapter-18/image-045.png)

![AgentLoop 数据飞轮实践（三）配图 12](../../assets/imgs/chapter-18/image-046.png)

*图 7：采样配置：按需限制评估数据量（视频 30:45）*

### 4. 配置字段映射

最后一步把数据字段连到评估器声明的变量上（图 8）：`trace.input` 映射到 `input`、`trace.output` 映射到 `output`、轨迹数据映射到 `trace.agent`。连对线，保存运行。

## 六、小结

| 环节 | 关键点 |
| --- | --- |
| 黄金指标 | 从业务场景出发（回答质量 + 执行过程），可 AI 辅助拆解 |
| Rubric | 每个指标的评分标准 + 权重 → 加权总分，让评估可复现 |
| 评估器 | 类型 Agent/Code；变量 input/output/轨迹；结构化输出定义（分数 + 解释 + 证据） |
| 评估任务 | 轨迹数据、持续/历史策略、采样降本、字段映射 |
| 结果消费 | 分数 + 解释 + 证据；badcase 沉淀数据集进入实验 |

一句话总结评估的作用：**把专家头脑里模糊的「好不好」，变成机器可执行、结果带证据的硬标准。** 有了同一把尺子，后面的优化实验才真正有账可算。
