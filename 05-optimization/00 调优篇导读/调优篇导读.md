# 调优篇导读

调优篇解决一个很现实的问题：**Agent 上线跑起来以后，怎样把每次运行暴露出来的不足，持续变成真本事？** 前面的架构、构建、运行和治理决定系统能不能稳稳跑起来，调优篇则决定这套投入能不能越跑越好、越跑越省。

动手调优前，最容易踩的坑就是「头痛医头，看到报错就想去训模型」。事实上，线上出问题往往有两个截然不同的源头：问题可能藏在模型权重里，但更多时候是 Agent 没拿全上下文、工具说明含糊、状态没管住，或者干脆是外部服务挂了。因此本篇按「先归因、再下手」的逻辑拆成两条主线，外加一章按需选读的边缘专题：

| 对应章节 | 结构 | 优化对象或主题 | 主要方法 |
| --- | --- | --- | --- |
| 第 17 章 | 模型调优 | 模型的理解、决策、工具使用与失败恢复能力。 | 监督微调（SFT）、Agentic RL（RLVR）、模型蒸馏，以及在完整 Agent 中的上线验收；另附推理框架的基础原理。 |
| 第 18–23 章 | 智能体调优 | Harness、数据与评估闭环、经验与 Skill、运行反馈。 | 数据飞轮：Trajectory、声明式 Pipeline、黄金数据集、持续评估与实验、Badcase 修复、受控自进化。 |
| 第 24 章 | 专题延伸 | 全球交付与边缘优化。 | 边缘运行时、边缘评估、性能与成本优化、内容分发、边缘安全与边缘仿真。 |

**第一条主线是模型调优（第 17 章）。** 只有当模型拿到了准确信息、看懂了清晰的工具接口、运行环境也完全正常，它还是会在不同问法下反复犯同一类判断错误时，才真正轮到修改模型权重。模型训练是成本最高、周期最长的手段，第 17 章先帮你把「什么时候千万别微调」的判据立住，再拆解 SFT、Agentic RL 与蒸馏各自怎么练、怎么进完整 Agent 验收；同时讲透推理框架怎么左右首字等待时间、并发吞吐和缓存账单。

**第二条主线是智能体调优（第 18–23 章）。** 现实中绝大多数效果短板并不在模型脑子里，而在外层的 Harness（上下文拼装、工具协议、状态管理、权限护栏）以及团队有没有一套能转起来的改错机制。这条主线以「数据飞轮」为核心：先把分散日志穿成可读的行为轨迹（Trajectory），再用声明式 Pipeline 洗成带判据的黄金数据集，接着跑持续评估和对照实验抓住 Badcase，最后把验证有效的经验、Skill 和运行改进稳妥带回线上，做到受控自进化。

**第 24 章是面向全球交付的按需专题。** 如果你的 Agent 要服务跨区域甚至全球用户，单靠机房内调优还不够——跨网传输慢、重复问题反复算、边缘节点安全前置和就近路由都会直接拖垮体验与成本。这一章和前两条主线没有先后依赖，按业务覆盖范围按需选读即可。

两条主线也没有谁先谁后、谁高谁低，决定你走哪条路的永远是归因顺序：**先排查是不是执行环境本身出了故障，再检查 Harness 给模型的上下文和工具约束有没有漏洞，两项都排除了，才去动模型。** 找准病根再开药，才能避免拿昂贵的模型训练去补系统代码的漏洞，或者用一堆补丁掩盖模型本身的能力短板。
