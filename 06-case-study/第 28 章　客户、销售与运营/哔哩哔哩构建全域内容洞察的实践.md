# 哔哩哔哩构建全域内容洞察的实践

> **阅读提示**：本案例实质上是 B 站商业化数据科学团队落地的一套**“大模型抽标签口径 + 领域微调小模型库内推理”多模态数据洞察流水线**（依托百炼、PAI、自研平台与 PolarDB for AI 运行），重点解决低成本高并发的视频结构化、标准品名对齐与海量评论噪声过滤，而非典型的多步对话式 Agent。

---

## 一、痛点：用户看了 UP 主视频被“种草”，广告主怎么拿数据算账？

跟货架电商“看了直接下单”不同，B 站用户往往是在视频、图文、直播、动态和评论区互动中慢慢攒出品牌心智和消费意愿。B 站商业化团队在用去标识化、匿名化的公开互动数据帮广告主做效果评估与策略洞察时，撞上三道硬墙：

![image.png](../../assets/imgs/chapter-28/image-005.png)

1. **种草效果难量化**：车企发了一批新车测评视频，广告主想知道大家在讨论续航、外观还是价格、好评多还是吐槽多，靠人工刷评根本统计不过来。
2. **内容结构太杂**：核心信息散落在视频画面、口播、字幕和弹幕评论里，常规关键词匹配和老规则引擎根本认不出复杂语境下的品牌、类目和具体型号（SPU）。
3. **反向指导新品缺数据**：美妆品牌想知道用户聊粉底液时最在意“持妆度”“遮瑕力”还是“肤感”，需要跨视频和评论的细粒度属性洞察。

---

## 二、整体解法：大模型搭矩阵 + 小模型进数据库跑推理

如果全部视频帧和评论都拿千亿参数大模型硬扫，算力账单直接爆炸。B 站与阿里云采取了**“通用大模型 + 领域微调小模型”协同**、并把小模型推理直接下沉到 **PolarDB for AI** 节点里的务实路线，撑起覆盖 `M` 个商业标签维度 × `N` 种内容体裁的全域洞察矩阵：

![image.png](../../assets/imgs/chapter-28/image-006.png)

![image.png](../../assets/imgs/chapter-28/image-007.png)

整套三层技术架构的分工很清楚：

- **AI 基建层**：基于阿里云百炼、PAI、GPU 资源与 B 站自研平台完成模型微调（SFT、强化学习）和推理调度。
- **数据与模型层**：DeepSeek、通义千问（Qwen / Qwen-VL / Qwen-Audio）及 B 站自研 Index 大模型负责挖掘新标签体系、读复杂多模态语义；经微调的领域小模型专攻高并发、低延迟的实体抽取与对齐任务。
- **应用服务层**：利用 **PolarDB for AI** 把领域小模型直接挂在数据库内部运行，实现**“数据不出库”**——既避免海量数据在数据库和推理集群之间反复搬运、降低了工程链路复杂度与安全风险，又把日常高频推理成本压下来。

## 三、两个最核心的技术关卡与工程破局

### 1. 视频稿件提取：怎么把“尼康 Z5”精确挂靠到标准商品库？

![image.png](../../assets/imgs/chapter-28/image-008.png)

视频信息分散在画面、语音和字幕里，B 站先用三步完成结构化提取：

1. **生成语义中间层**：先跑 ASR（语音转文字）和关键帧 OCR（画面文字识别），再配合 Qwen-VL、Qwen-Audio 多模态大模型合成统一的语义中间表示；
2. **建 CPV 属性体系**：挖掘并维护“类目—属性—属性值”体系（比如识别出“相机”类目下的“防抖技术”属性为 `IBIS`）；
3. **抽三元组并对齐标准库（最大难点）**：模型从非标口播里抽出来的可能是 `"尼康Z5"`，而阿里标准商品库里的标准 SPU 叫 `"尼康Z5微单相机"`——名字对不上，后续统计全废。

为了解决“名字对不上”的实体对齐难题，团队配合 BGE+RoBERTa 匹配模型与商品知识图谱，并直接在 **PolarDB for AI** 中用一条 SQL 调用微调后的定制对齐模型，做到高并发库内预测：

```sql
/*polar4ai*/ 
SELECT * FROM PREDICT(
  MODEL _polar4ai_cpv_agent, 
  SELECT '{"商品名称":"尼康Z5","品牌名称":"尼康","类目属性模板":{"类目":""},"类目属性限定":{"类目":["数码-摄影摄像-传统相机-相机","数码-数码配件",...]}}'
) WITH ();
```

返回标准化结果：`{"类目"："数码-摄影摄像-传统相机-相机"}`。数据不用搬出数据库，一条查询就能拿到对齐后的标准分类。

### 2. 海量评论区分析：先用轻量模型滤掉 90% 无关废话

![image.png](../../assets/imgs/chapter-28/image-009.png)

B 站评论区互动极活跃，但 **90% 以上属于玩梗、闲聊等非商业化内容**。拿大模型全量硬跑评论区完全不划算。B 站为此搭了一套三级漏斗流水线处理匿名化互动数据：

1. **一级商业化过滤（省算力关键一步）**：先用轻量级 NLP 模型（`BGE + BiLSTM`）高速筛掉 90% 以上的非商业噪音，只留下真正聊到品牌或产品的评论；
2. **二级实体与关系抽取**：对漏斗留下来的高价值文本，用部署在 PolarDB for AI 里的商品领域大模型识别类目、品牌、SPU 及相互关联；
3. **三级高阶意图与属性深挖**：进一步识别群体讨论里的“种草”“购买意愿”以及关注的具体卖点（如“续航达成率高”“价格贵”），沉淀成结构化洞察指标。

## 四、业务落地：这套洞察体系跑在了哪些真实产品里？

目前这套结合了通义千问与 PolarDB for AI 库内小模型推理的洞察体系，已经直接支撑起 B 站多条核心商业化产品线：**哔哩指数、花火平台 AI 选 UP 主、哔哩必达洞察报告、引力计划爆文投放、经营号线索挖掘以及品牌广告搜索词包**，把原本停留在非结构化视频和弹幕里的社区讨论，真正变成了可衡量、可指导投放和新品策略的结构化商业指标。
