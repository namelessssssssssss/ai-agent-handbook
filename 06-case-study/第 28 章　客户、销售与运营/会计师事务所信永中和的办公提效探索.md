# 会计师事务所信永中和的办公提效探索

> 💡 **省流导读卡（原文体裁：云产品落地案例）**
> 1. **真实业务问题**：信永中和（源起于 1981 年，全球 23 个国家地区设 110 个办公室、超 1.2 万名员工）内部 AI 应用增多后，需要把制度问答、OA 填报、企查风控等散点助手整合到统一入口，并解决模型容灾、权限管控和合规审计难题。
> 2. **实际底层技术**：原文是标准的企业云平台接入实践，核心依托阿里云 **AgentCore**（统一管理模型、MCP Server、Skill 与多智能体路由）与 **AI 网关**（主备模型切换、按部门计费、敏感信息防护、全链路调用审计）在一周内完成联调上线；未披露具体 Agent 内部实现细节或量化提效指标。
> 3. **值得留下的唯一工程启示**：强合规要求的大型专业服务机构推进 AI 办公时，先用 MCP 把内部 OA 和知识库转成受控标准接口，再用 AI 网关收口模型路由、权限与审计账单，比各自直连模型更容易在短周期内过安全合规关。

## 一、背景：从零散问答助手，转向统一可控的企业级多 Agent 底座

信永中和业务横跨审计鉴证、管理咨询、税务服务、工程管理四大板块，对信息安全、数据保护和业务合规有刚性要求。随着内部 AI 场景越建越多，单个孤立助手的玩法走到头了——员工每次要自己找不同工具入口，内部 OA/知识库接口各自对接混乱，模型调用成本与审计也管不住。

信永中和选择负责整体业务规划、知识整理与内部系统集成，同时引入阿里云 **AgentCore** 与 **AI 网关** 搭起统一底座。上线关键阶段双方协同联调，用**一周时间**完成环境配置、系统接入与测试并正式对内开放。

## 二、落地架构：AgentCore 管能力与协同，AI 网关守安全与成本

整套底座分成“能力组织”和“流量治理”两块：

### 1. 基于 AgentCore 的统一入口与四大首批场景

平台把不同业务领域的模型、MCP Server、Skill 和 Agent 模板收归集中管理，并通过统一入口对员工服务——员工不用分辨后台有多少个 Agent，直接用自然语言提需求，由管理 Agent 自动识别任务类型、拆解多步任务并汇总结果。内部既有系统通过 MCP Server 封装为标准化能力，使 Agent 能在授权范围内查询与执行操作。

首批落地的四类典型智能体：

- **制度与流程问答 Agent**：接内部知识库，用自然语言查内部规章和办事流程，减少跨部门问询。
- **OA 集成 Agent**：直连办公系统，在对话中完成工时查询与工时填报。
- **企业信息查询 Agent**：核查企业工商信息、股东结构、关联关系与风险信号，辅助客户背调与项目立项评估。
- **文档处理与汇报辅助 Agent**：协助完成长文档提炼、总结和汇报框架起草。

### 2. 基于 AI 网关的统一模型治理与审计合规

大模型调用全部收口经过阿里云 AI 网关，重点落地四项治理动作：

- **主备多模型切换**：主模型出现延迟或异常时按预设策略自动切至备用模型，稳住服务连续性。
- **按部门精细化计量**：统计各部门、各 Agent、各模型的调用量与 Token 消耗，支撑内部预算与成本分摊。
- **分级授权与凭证隔离**：按不同 Agent 的职责限定可调用的模型和内部系统权限边界，禁止越权访问。
- **全链路安全防护与可追溯审计**：在请求/响应侧挂载敏感信息识别与内容安全检测，并完整记录“哪位员工、何时、通过哪个 Agent、调了哪些接口、干了什么”，满足审计回溯要求。

## 三、阶段成效与后续方向

上线后，信永中和收拢了分散的办公 AI 入口，把知识查询和工时填报等高频事项统进对话入口，并为后续新增智能体建立了标准化的接入与安全基线。后续计划随着更多内部系统以 MCP 方式开放接口，逐步将能力从“制度问答与信息查询”继续向经营数据分析、跨系统任务协同和项目管理辅助延伸。
