# 从单点探索到规模化运营：滔搏体育的企业级智能体实践

先代入一位门店店长的视角：周末快到了，店长要排一套周末经营计划——听着是件小事，背后却得翻销售报表、核库存尺码、挑出该重点回访的会员，再把动作拆给店员。如果把这事交给 AI，它到底能帮到哪一步？

## 一、背景：几千家门店不能全指望“最懂行的那一个人”

在滔搏，这不是某一位店长的偶发需求。滔搏在全国有 **4,360 家实体门店**、**超过 3,700 家小程序店铺**，长期合作 **20 多个运动品牌**，累计会员用户 **超过 9,000 万**。单看一家店，经营卡壳了可以请资深督导来聊；但面对几千家门店，最有经验的人不可能同时分身站进每一家店。

滔搏想做的事情很实在：**把总部和金牌店长反复验证过的零售经验，变成所有门店随时调得动的专业能力。** 但一线岗位不一样，要的东西完全不同——店员问的是“这双鞋怎么给顾客讲卖点、我该补练什么话术”；店长问的是“到底哪项业绩掉了、下一步怎么调经营、哪些老客今天该维护”。目标彼此咬合，需要的数据、知识和权限却各不相同，因此不可能靠一个大一统聊天机器人解决，而是必须按岗位职责做多个专业 Agent。

![滔搏为什么需要多个企业级 Agent：协作一线员工、店长与经营管理、业务运营三类岗位需求](../../assets/imgs/chapter-28/image-014.jpg)

## 二、真做多 Agent 之后才撞上的六个难题

刚做第一个 Agent 时往往挺顺，一旦打算做第 2 个、第 10 个，很快就会发现：**单个 Agent 能跑通，绝不等于多个 Agent 拼在一起就能把业务干成。**

![规模化运营的六个难点：重复建设、协作困难、权限治理、效果衡量、问题定位、共同运营](../../assets/imgs/chapter-28/image-015.jpg)

实际规模化运营时集中撞出六个难题：

1. **重复造轮子**：同样的商品数据、库存接口、会员知识，每起一个新项目就得从头接一遍。
2. **跨角色断链**：经营分析 Agent 跑完了，结果怎么接给会员 Agent 和营销 Agent 继续往下干？
3. **权限一团麻**：能力可以全公司共用，数据绝对不能乱串——怎么确保店长只看得见自己门店的数据？
4. **效果说不清**：调用量看着很高，到底帮业务多卖了货还是制造了阅读负担？
5. **出错追不到**：多 Agent 串起来答偏了，到底是上游取数错、Skill 逻辑错还是模型理解偏？
6. **上线即失联**：项目验收一过，谁来盯着它随业务规则变化持续迭代？

这六个问题不可能靠每个小项目组各打各的补丁。滔搏选择用 **AgentCore** 当统一的智能体构建与治理底座（统一管理模型、MCP 工具、Skill、Workspace 与角色权限隔离，并用 Agent Team 组织跨专业协作），同时接上 **AgentLoop** 做持续观测、根因追踪和效果评测——目标是做到“建第 2 个 Agent 不用从零搭架子，管到第 10 个也不乱”。

![AgentCore 企业级智能体运营底座：构建与运行、协作与治理、观测与评估](../../assets/imgs/chapter-28/image-016.jpg)

## 三、底座搭在“零售实战”上：三个真实业务场景

平台本身不懂卖鞋，什么结果算合格、哪些动作必须店长拍板，还得由业务自己定义。滔搏在底座之上铺了一套分层零售架构：底层是业务数据、知识和 MCP/API 接口 → 中间抽出一层可复用的专业 **Skill**（查商品、查库存、会员分群）→ 上面长出经营、商品、陪练、会员、营销等专业 Agent，由 Team Leader 统合响应用户的自然语言需求——员工不用记住自己该找哪个 Agent。

![滔搏零售 Agent 体系：基础资源、可复用 Skill、专业 Agent、Agent Team 与业务入口](../../assets/imgs/chapter-28/image-017.jpg)

### 场景 1：一线练货——别一看到卖得差就逼店员背话术

![一线练货：经营、商品与陪练 Agent 协作，将销售偏差转化为针对性练货任务](../../assets/imgs/chapter-28/image-018.jpg)

传统门店培训最大的问题是“一刀切”。滔搏把三个专业能力串起来干这件事：首先**经营 Agent** 发现某款商品销售表现掉队，但绝不草率下结论“店员不会卖”，而是先结合门店现场反馈核实是不是缺货、陈列或定价等外部原因；确认真是导购讲解短板后，**商品 Agent** 调出卖点和穿搭建议，**陪练 Agent** 再针对性拉起互动演练；练完也不是打个分就完事，评分和薄弱项会回流到助手里用来安排后续补练。

单月统计显示，这套练货体系覆盖了 **超过 5,700 件商品**、累计练货 **超过 39 万次**。但滔搏团队自己非常清醒：**使用次数多只代表工具推下去了，真正值钱的是训练到底有没有转化成导购站在柜台前的真实服务水平提升。**

### 场景 2：线上小程序线索挖掘——不要再给一个人干活的店长多发一份报告

![线索挖掘：经营、会员、商品与营销 Agent 协作，生成店长每日顾客维护任务](../../assets/imgs/chapter-28/image-019.jpg)

线上小程序店往往只有店长一个光杆司令，看数据、挑顾客、配货、发消息全压在一个人肩上。**如果 AI 只是每天再吐出一份洋洋洒洒的分析报告，店长的阅读负担反而变重了，工作量一点没减。**

因此在这个场景里，经营 Agent 和会员 Agent 先筛出当天最该跟进的高潜顾客，商品 Agent 接着匹配顾客历史偏好和门店实际可售库存，营销 Agent 顺手把沟通话术和触达切入点准备好——最后推到店长面前的不是一张长图报表，而是一张**“点确认就能直接联系这几位顾客”的当日任务清单**，回访和成交结果再反哺下一轮维护。

### 场景 3：门店周末经营安排——复用同一套 Skill，但数据权限锁死在本店

![门店经营探索：复用经营、商品库存和会员能力，形成可执行的周末运营计划](../../assets/imgs/chapter-28/image-020.jpg)

回到开场那个问题。店长提出“怎么排周末经营计划”这种没有固定按钮的开放问题时，AI 助手后台会跨经营、商品库存、会员三个域拉数综合出主推款、陈列调整和老客激活方案，店长再追问微调并最终确认。

这里死守一条铁律：**全公司共用一套 Agent 能力和 Skill，绝不等于打通所有门店数据——店长会话里永远只能拉取本店授权范围内的业务数据。** 在单次经营分析案例中，店长跨系统拉数拼装方案的耗时**从 2 小时压缩到了约 20 分钟**，省出的精力全部留给了真正的经营判断。

## 四、从“做通一个店”到“全集团可复制”：把套路冻成 SOP 型 Skill

一家店跑顺了，绝不能下一家店又从头写一套 Prompt。滔搏总结了一套四步规模化方法：**选高频刚需、定验收标尺 → 沉淀资产 → 共同运营 → 持续优胜劣汰**，做完每个场景必答两个问题：“这次解决了什么真问题？下一次能给别人留下一件什么可复用资产？”

![落地方法：选择场景、沉淀资产、共同运营与持续进化](../../assets/imgs/chapter-28/image-021.jpg)

沉淀下来最抗打的资产，叫 **SOP 型 Skill**。对于已经跑出标准解法的经营分析或训练套路，不需要让模型每次重新“灵机一动”自由发挥，而是把标准解法编成可被稳定调度的 Skill——写清**适用条件、输入清洗、依次调用什么工具、输出规范、遇到异常怎么兜底、以及哪一步必须停下来让店长/业务确认**。

![SOP 型 Skill：把经过业务验证的问题解决记录沉淀为可复用能力](../../assets/imgs/chapter-28/image-022.jpg)

注意：SOP 型 Skill 不是写进文档里躺着的说明书，它必须像正式软件组件一样**带版本号、指定唯一负责人、配齐评测基准**，经过反复验真后再组合成专业 Agent。

## 五、防“Agent 上线，责任下线”：业务、IT、AI 团队同桌算双闭环的账

零售的促销政策、库存结构和会员玩法每个月都在变，如果按传统 IT 外包“交付完验收走人”的模式搞，用不了两个月系统就废了——这就是最常见的**“Agent 上线了，责任却下线了”**。

![业务部门、IT 团队与 AI 团队共同运营企业智能能力的责任分工](../../assets/imgs/chapter-28/image-023.jpg)

滔搏把三方绑在同一个运营桌子上，但权责切分得极其清楚：

- **业务团队**：最懂痛点和评判尺子，担任场景负责人，定验收标准并追踪经营结果；
- **IT 团队**：兜住系统集成、权限隔离和生产稳定性；
- **AI 团队**：负责 Agent 工程基建、公共能力、评测集和版本调优。

上线后三方共同盯着四类指标做优胜劣汰：**使用与采纳**（业务到底采没采纳建议）、**质量与可靠性**（准确率与人工兜底率）、**效率与单次成本**、**真实业务价值**（方案落地后卖得有没有更好）——该加码的继续投，长期没效果的场景果断下线或改版。

![持续衡量指标：使用与采纳、质量与可靠性、效率与成本、业务价值](../../assets/imgs/chapter-28/image-024.jpg)

背后靠两股闭环咬合推进：**AgentLoop** 盯着技术和能力怎么变准，**Business Loop** 盯着门店经营问题到底解决没解决。练货效果不好，顺着反馈查是需求识别错、商品资料错还是话术评估偏；顾客维护转化低，回去查是圈人策略偏了还是沟通内容没打中——只有真实业务反馈流回 Skill 和 Agent 的版本更新里，飞轮才算真正转起来。

![AgentLoop 与 Business Loop 双闭环：业务反馈推动能力升级](../../assets/imgs/chapter-28/image-025.jpg)
