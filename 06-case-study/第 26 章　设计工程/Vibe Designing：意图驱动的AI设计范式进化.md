# Vibe Designing：意图驱动的AI设计范式进化

AI 进设计圈已经好几年了，大家从聊 Prompt、练 LoRA 聊到拼 Workflow。但真正改写工作逻辑的变化发生在最近大半年：**AI Coding 正在从程序员的专属工具，变成所有人都能用自然语言表达意图、亲手做出能跑能用产品的通用创造力。**

![ai是一道光.gif](../../assets/imgs/chapter-26/image-013.gif)

对设计师而言，这不只是“设计师也会写几行代码了”，而是脑子里的想法终于可以跳过漫长的排期等待，自己快速变成能运行、能验证、能让别人直接上手使用的真实作品。

---

## 一、从个人小工具到高校课堂：AI Coding 正在打破专业壁垒

这场变化已经在三个不同层面发生：

- **个人破局**：阿里云设计师用 AI Coding 自己做了个效率小工具并发布到 npm，两天内就拿到 150 多次下载——遇到痛点不再只是等排期，自己就能动手造工具。
- **团队重塑**：阿里云设计中心举办全员 Vibe Designing Jam，围绕“智能体优先”的工作方式交出了 40 多个参赛作品，覆盖产品设计、市场传播、体验度量等方向。

![jam.gif](../../assets/imgs/chapter-26/image-014.gif)

- **教育延伸**：浙江大学艺术与考古学院陈晓皎老师把 AI Coding 带进文化计算课程，带着学生围绕傩文化、传统乐器做出能交互、能运行的数字叙事系统，让文化设计不再只能停在静态海报或画风迁移上。

## 二、真用起来才发现的痛点：意图说得很快，结果却像“默认模板”

人人都用自然语言提需求之后，一个尴尬立刻冒出来：**裸模型并不懂你的业务语境，也不懂你的设计语言。** 哪怕你反复用聊天窗口“这里调窄一点、那里风格不对”来回修正，出来的东西依然散发着一股廉价的默认模板味，既没品牌气质，也不贴合业务流程。

![意图驱动的AI设计新范式_0710.047.png](../../assets/imgs/chapter-26/image-016.png)

核心问题浮出水面：**一个模糊意图，靠什么稳定长成高质量的产品体验？**

中间靠的绝对不是某个神奇 Prompt，而是一套系统化的能力底座——**设计师必须从“单兵用 AI 工具画图”，转型成“为 Agent 搭建设计能力系统的人”**。阿里云把这个能力体系沉淀为 **CloudAI Design**，由三层互为支撑的结构组成：**设计工程（研发态打底）**、**动态交互（运行态组织）**、**自我进化（体验反馈牵引）**。

---

## 三、第一层 · 设计工程（Design is the New Code）：把设计师的判断编成 Agent 资产

设计工程不靠继续叠长篇大论的 Prompt，而是打开 Agent 生成链路的黑盒，把设计师脑子里的组件规范、业务语义、交互原则和验收标准工程化，让 Agent 在你的语境里而不是在“互联网默认审美”里生成界面。

![意图驱动的AI设计新范式_0710.016.png](../../assets/imgs/chapter-26/image-017.png)

CloudAI 把设计工程拆成两类资产：

- **设计声明（回答“什么是好设计”）**：把产品结构、业务语义、视觉风格、组件约束和体验底线定义清楚，给 Agent 划好真实语境边界。
- **执行契约（回答“怎么一步步做出好设计”）**：把设计师干活的方法论、检查流程和判断顺序封装成 Agent 可调用的规则和步骤，控制生成过程而不是事后碰运气。

![意图驱动的AI设计新范式_0710.017.png](../../assets/imgs/chapter-26/image-018.png)

这套能力已经用在阿里云多款 AI Native 商业产品（Agent 构建、运维、观测、安全等）研发里：Agent 借助 CloudAI 快速产出高质量的工程基线界面；碰到交互极复杂或审美要求极高的页面，设计师再用 Figma MCP 等工具精修，并把精修总结出的新组件、新规矩反哺回设计资产库。

---

## 四、第二层 · 动态交互（GenUI is the New Interface）：从 UX 走向 AX

传统软件是把菜单、按钮和路径提前焊死，用户得自己去学系统怎么用（UX）；而 AI Native 应用是从**“人学系统”反转为“Agent 顺着人的意图实时组织操作界面”**，即从 UX 转向 **AX（Agent Experience）**。

![意图驱动的AI设计新范式_0710.029.png](../../assets/imgs/chapter-26/image-019.png)

如果说设计工程解决的是研发构建态，**动态交互（GenUI）** 解决的就是运行态体验。

![image.png](../../assets/imgs/chapter-26/image-020.png)

举个例子：一位用户想在云上训练机械臂模型。按老界面，他必须自己翻懂平台入口在哪、选哪个算法框架、配多少算力、填哪些超参，走完一长串表单。而在 GenUI 模式下，他只需说出意图“我想训练一个机械臂模型”，Agent 就会结合平台能力和当前上下文，动态拼出一个当次任务专属的过程界面——列出推荐算法、方案对比和资源参数，用户直接确认或微调就能往下推，用完即走，不再被僵死菜单框住。

---

## 五、第三层 · 自我进化（Taste is the New Engine）：用品味拉高上限，而不是停在“还凑合”

大模型很容易在第一轮就给你一个“看着还行、其实经不起推敲”的 60 分基线。如果不靠人一轮轮盯着返工，Agent 怎么能自己往 90 分走？

![意图驱动的AI设计新范式_0710.037.png](../../assets/imgs/chapter-26/image-021.png)

答案靠两条腿走路：**质量兜底 + Taste（品味）牵引**。质量关注语义没错、业务合规、交互不卡顿、视觉统一；而品味关乎文化叙事、产品气质和微小却致命的交互分寸。

![意图驱动的AI设计新范式_0710.038.png](../../assets/imgs/chapter-26/image-022.png)

自我进化的关键机制，是把质量规则和品味判断写进自动评测器（Evaluator）与体验巡检里：Agent 每生成一轮，先让 Evaluator 自己挑毛病、出修改意见，再把修改反馈喂进下一轮重生成。

![image.png](../../assets/imgs/chapter-26/image-023.png)

这不是要把艺术审美庸俗地公式化，而是给 Agent 装上一面不断照镜子的校准器——让它分清“功能凑合能用”和“体验真正打动人”之间隔着哪几处细节。

---

## 六、结语：设计师依然靠作品说话，只是“作品”长出了新形态

在 AI 时代，设计师的核心价值没有变，变的只是交付的载体：你交出的可能不再只是一张静态切图或 Figma 稿，而是一个能直接运行交互的动态原型、一套能被全团队 Agent 调用的 Design Skill、一组自动拦截坏体验的巡检评测器，或者一套支撑 Runtime 动态拼装的 GenUI 规则底座。

![意图驱动的AI设计新范式_0710.048.png](../../assets/imgs/chapter-26/image-024.png)

**Vibe Designing 真正要解决的，不是“如何用 AI 随便出图”，而是当人人都能靠自然语言生成软件时，设计师如何把专业判断、业务理解与审美品味封装成基础设施，拉高整个组织产出的体验下限与上限。**
