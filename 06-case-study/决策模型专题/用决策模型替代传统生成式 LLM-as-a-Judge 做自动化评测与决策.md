# 用决策模型替代传统生成式 LLM-as-a-Judge 做自动化评测/决策

## 前言

Decision Model（Jev 这类结构化决策模型）在自动化评测和线上风控里潜力很大，但它并不是接上 API 就能直接裸奔的“魔法黑盒”——上线前必须先做好阈值调优与概率校准这两道基本功。

本文前半部分（01—02 节）编译并整理自 Hamel Husain 与 Antaripa Saha 合著的《How To Use Decision Models for Evals》，聚焦一个最常见的落地陷阱：**用决策模型替代传统生成式 LLM-as-a-Judge 时，直接照搬默认 `0.50` 阈值和原始输出概率会白白丢掉一大截性能，甚至造成严重误判。** 后半部分（03—04 节）则是笔者结合统计推导与模型训练视角整理的工程深潜笔记。

## 01 为什么要用决策模型替代传统生成式裁判？

在搭建自动化评测（Automated Evals）流水线时，大家最习惯拿通用生成式大模型当裁判（LLM-as-a-Judge）。但真把评测推向高频线上调用时，生成式裁判很快就会撞上两道绕不过去的墙：

第一道墙是**生成开销太重**。哪怕业务代码最后只需要一个 `Pass` 或 `Fail` 的二元结论，自回归大模型还是得老老实实一个 token 接一个 token 地把推理过程或 JSON 框吐出来，时延和 API 账单很难压下去。

第二道墙更隐蔽，却更致命：**传统生成式裁判给不出连续、可信的置信度信号**：

- 如果让 LLM 直接输出离散的 `Pass` 或 `Fail`，等于让模型在黑盒里悄悄替你做了一刀切——外层程序拿不到任何概率梯度，既没法按业务容忍度去拉高或放宽误报（False Positive）与漏报（False Negative）比例，也看不出哪些样本正卡在模棱两可的灰区。
- 如果在 Prompt 里要求模型顺便“口头打个分”（比如输出 `{"score": 0.85}`），它本质上只是在采样数字字符。受预训练语料分布影响，模型吐出来的分数高度扎堆在 `0.50`、`0.80`、`0.90` 这几个整数档位上，既不连续，也往往跟真实出错率对不上号。
- 就算退一步去读取答案 token（比如 `Yes` / `No`）上的 `logprobs`，由于通用大模型普遍做过好几轮人类偏好对齐（RLHF）或 0/1 奖励的 GRPO 训练，它的词表概率早就被推向极端——输出动辄坍缩在 `0.999` 或 `0.001`，同样失去了灰区样本的区分度。

**决策模型**（Decision Models）正是冲着这两个瓶颈设计的。从 TypeSafe 的 Jev 开始，Perplexity 的 Decider、Liquid 的 d1、Cloudflare 的 Clef 以及 OpenAI 的 Decisions API 陆续跟进。它们砍掉了逐字生成文本的循环，**单次前向计算直接从专用决策头读出 logits，并映射成 $0$ 到 $1$ 之间的连续概率分数**。

拿到连续概率后，工程侧立刻多了很多可操作空间：不仅省下了生成长文本的算力和时间，还能**自由滑动决策阈值**来平衡误报和漏报，甚至直接把概率当成**风险分数**做分级路由（高危拦截、灰区转人工、低危放行）。

但坑往往就踩在这里：很多团队接入后，**直接沿用 API 默认的 `0.50` 门槛切分好坏，也从未验证模型报出来的分数究竟准不准**。下面我们用一组真实评测实验，把“怎么挑模型、怎么在交叉验证下调阈值、怎么验概率校准”一步步拆清楚。

## 02 实验实测：怎么用决策模型做出靠谱评测？

### 1. 我们测了什么：任务设定与参评模型

实验从一套公寓租赁 Agent 系统中抽取出 **100 条真实运行轨迹（traces）**，每条轨迹都带着完整的对话历史和 Agent 调用动作日志。评测任务是在这些轨迹里抓出含错误的案例——比如该预订时预订失败，或者用户明确要求转人工客服却被漏转（这也是我们之前自动化评测文章里用过的“广义找错”数据集）。

同一套评测准则发给以下 6 个决策模型，分别让它们给出每条轨迹包含错误的概率（failure probability）：

- **TypeSafe Jev 1.13**（按其规范改写为结构化输入）
- **Perplexity Decider 1.1 27B**
- **Liquid d1** 与 **Liquid d1-ultra**
- **Cloudflare Clef Flash**
- **OpenAI Decisions（底层为 GPT-6 Luna）**

评测从两个维度对照（本次暂不比时延，因为时延极大程度受实验外部的服务端环境影响）：
1. **分类性能**：拿模型预测对比人工逐条核验标好的 `pass` / `fail` 真值，看它能不能抓准错误同时少放假警报；
2. **调用成本**：依据实际 token 消耗和官方定价核算每百次评测费用。

### 2. 理解决策阈值：为什么默认 `0.50` 会坑人？

每条轨迹收到的标签只有两种：`pass` 或 `fail`。做自动化评测时，二分类设定能倒逼团队把评判标准写明白，也最容易和人工标注对齐。

决策模型会为每条轨迹吐出一个 $0$ 到 $1$ 的风险分，各家 API 默认以 **`0.50` 作为切分线**（$\ge 0.50$ 判失败，否则判通过）。但如果不拿自己的业务样本核对就直接套用 `0.50`，结果可能非常荒唐。

举个极端的例子：假设某模型给所有真失败轨迹都打 `0.40` 分，给所有正常轨迹都打 `0.10` 分。其实这模型把好坏分得清清楚楚——只要把阈值往左挪到 `0.30`，它立刻能拿 100% 准确率；可要是傻傻死守默认的 `0.50`，它一条错误都抓不出来。

真实业务里正负样本的打分难免有重叠，挪动阈值本质上是在权衡一对老搭档：

- **Precision（精确率 / 查准率）**：被模型判成失败的轨迹里，有多少条是真的错了（控制误报骚扰）；
- **Recall（召回率 / 查全率）**：所有真出了错的轨迹里，被模型揪出了多少条（控制漏报逃逸）。

该偏重哪一头完全看业务后果：刑事定罪讲究“宁可放过不可冤枉”，死卡高 Precision；早期癌症筛查讲究“宁可复查不可漏诊”，死守高 Recall。

![六个决策模型的失败与正常轨迹分数分布及决策阈值](../../assets/imgs/jev/judge-evals-01.png)

为了站在同一条起跑线上比对这 6 个模型，我们先用等权调和平均 **F1 分数**（$0$ 到 $1$，越高越好）来统一衡量。把每个模型给失败轨迹（橙色）与正常轨迹（蓝色）打出的分数分布摊开，并把阈值从默认 `0.50` 移到各自的最优 F1 位置后，能一眼看出：**OpenAI Decisions 把两类轨迹的分布拉开得最干净**，F1 也排在最前面。

### 3. 先立业务底线，再谈调优

千万别掉进另一个坑：**脱离业务底线去盲目追求最高 F1**。调阈值之前，必须先拍板“分类器至少要达到什么水平才算能上线”。

比如在搭建**自动化线上告警系统**时，如果要求 Precision 和 Recall 都必须至少达到 **80%**——既不能整天发假警报把值班同学累垮，也不能让超过五分之一的真故障从眼皮底下溜走。

![不同模型的 Precision-Recall 曲线及双 80% 合格区域](../../assets/imgs/jev/judge-evals-02.png)

把 6 个模型在不同阈值下跑出来的 Precision-Recall（PR）曲线画在同一张图上，右上角“Precision $\ge 80\%$ 且 Recall $\ge 80\%$”的矩形阴影区就是合格线。高下瞬间分明：

- **迈过合格线的候选模型（3 个）**：**Perplexity Decider 1.1 27B**、**Liquid d1-ultra** 和 **OpenAI Decisions** 的曲线穿进了阴影区；
- **直接淘汰的模型（3 个）**：**Jev 1.13**、**Liquid d1** 与 **Cloudflare Clef Flash** 无论怎么前后移动阈值，都没法同时踩进双 80% 区域，直接踢出候选池。

哪怕是留下的三个合格选手，各自也只有一小段曲线落在阴影区里——必须精准找到那一段里的最佳工作点。

### 4. 用交叉验证动手调优决策阈值

需要提前提醒一句：事后调阈值只能在既有的 PR 曲线上选点，改不了曲线本身的形状；如果自训模型时发现曲线压根够不到业务要求，就得回到训练阶段检查数据覆盖与训练目标，并在独立验证集上复核是否出现合格阈值（概率校准或单纯的阈值加权损失，本身都不保证 PR 曲线自动达标）。

接下来对刚才入围的三个候选模型，在**训练集上加上硬约束**：**只允许在同时满足 Precision $\ge 80\%$ 且 Recall $\ge 80\%$ 的阈值里挑最大 F1**；另外三个未达标模型则不设限直接最大化 F1，用来展示调阈值能救回多少分数。

为了防止“对着测试集看答案调参”导致线上虚高，务必上**分层五折交叉验证**。只要手里存好了历史打分和人工标注，把下面这段现成 Prompt 丢给 Coding Agent 就能跑出完整验证：

> Using my saved model scores and binary labels (1 means failure), tune a decision threshold to maximize F1 while requiring at least 80% precision and 80% recall. Use stratified five-fold cross-validation, choosing thresholds on the training examples and measuring performance on the remaining examples. If comparing models, use the same splits for each. Only select thresholds that meet both minimums on the training examples. If none qualifies, report that rather than relaxing either requirement. Report validation precision, recall, and F1, along with any splits where no threshold qualified or validation performance fell below my minimums. Compare with the default threshold of 0.50. Reuse the saved scores without making new model calls.

![默认阈值与五折交叉验证调优阈值的 F1 对比](../../assets/imgs/jev/judge-evals-03.png)

对比调优前后的 F1 变化，能看到两个很实在的规律：

- 淘汰池里的 Liquid d1 和 Clef Flash 调完阈值后 F1 涨幅反而更大（因为它们默认 `0.50` 偏离最佳切分点太远），但上限摆在那里，依然够不着双 80%；
- 入围的三位选手虽然涨幅相对温和，调优依然省不了——线上流量的几个百分点移动，往往直接对应人力审核成本；
- 现实业务很少真像 F1 那样把误报和漏报看得一样重。更在意误报率就改用 $\beta < 1$ 的 **$F_\beta$ 分数**，更怕漏报就用 $\beta > 1$；优化指标一换，选出来的最佳阈值和模型排名也会跟着变。

### 5. 性能与成本的较量：帕累托前沿怎么选？

各自调整到最佳阈值后，把三个合格候选的性能和每百次调用价格摆到一张图上比划：

| 达标候选模型 | 调优后 F1（5-fold CV） | API 成本（每 100 次评测） | 在帕累托前沿上的定位 |
| --- | --- | --- | --- |
| **Perplexity Decider 1.1 27B** | **0.79** | **0.82 美分** | 守住双 80% 底线的极致性价比首选 |
| **Liquid d1-ultra** | 介于 0.79～0.87 之间 | 介于 0.82～3.72 美分之间 | 性能与成本均处中档，且原生概率校准极好 |
| **OpenAI Decisions (GPT-6 Luna)** | **0.87** | **3.72 美分** | 分类精度断层领先，但成本约为 Perplexity 的 **4.5 倍** |

![决策模型的评测性能、调用成本与候选帕累托前沿](../../assets/imgs/jev/judge-evals-04.png)

连接这三个点的虚线就是本次候选池的**帕累托前沿（Pareto frontier）**——预算紧但过线就行选 Perplexity，追求极致精度且吃得消 4.5 倍账单上 OpenAI Decisions，看重中庸均衡与原生概率直接用选 Liquid d1-ultra。

### 6. 模型报出的概率能直接当真吗？（Calibration）

如果不仅想做二元切分，还想直接拿分数当**置信度估计**来分级处置（比如 0.90 自动拦截、0.50～0.80 人工复核），那就必须多问一句：**当模型报出 `0.80` 时，这批样本里是不是真的大约有 80% 出了错？**

把预测概率按高低分桶（每个桶大约 20 条样本），横轴画平均预测分，纵轴画这组样本真实的错误比例，就得到**概率校准曲线（Calibration Curve）**：
- **贴在对角线上**：说 80% 错就真错了 80%，最理想；
- **掉在对角线上方**：真实出错率比模型预测的还高，说明模型**低估了风险**；
- **掉在对角线下方**：实际出错没那么多，说明模型**高估了风险（一惊一乍）**。

![原始概率与 Platt scaling 后的概率校准曲线](../../assets/imgs/jev/judge-evals-05.png)

校准前的原生表现差异极夸张：**Jev 1.13 和 Liquid d1-ultra** 天然紧贴对角线，几乎不用修；而 **Cloudflare Clef Flash、Perplexity 与 Liquid d1** 明显跑偏——最离谱的是 Clef Flash，其中一组样本模型平均只报了 **8%** 的出错概率，真实结果里却足足错了 **60%**！

遇到概率不准，最经典的事后补救办法叫 **Platt scaling**——在留出集上拟合一条简单的 S 型映射曲线，把歪掉的分数扳回真实错误率。做完 Platt scaling 后，Perplexity、Liquid d1 和 Clef Flash 都乖乖贴回了对角线。但务必记住：**校准不是无脑正收益，OpenAI Decisions 在套用这一版 Platt scaling 后反而略微变差了**，必须用交叉验证下的 Brier 分数（越低越好）实测确认是否真修好了。同样附上可复现的验证 Prompt：

> Using my saved failure probabilities and binary labels (1 means failure), test whether Platt scaling improves each model’s probabilities. Use stratified five-fold cross-validation with the same splits for every model. Fit the calibration mapping on each training split and apply it to the remaining traces. Fit on log-odds, clipping probabilities away from 0 and 1 first. Plot predicted probabilities against observed failure rates before and after calibration. Report Brier scores (lower is better), and explain which models improved or got worse. Reuse the saved scores without making new model calls.

### 7. 评测粒度与四步迭代闭环

上面实验为了拉大差距故意测了一个宽泛任务（“找出任何错误”）。**但在真实业务里，强烈建议把大裁判拆成一组窄裁判，每一种具体失效模式单独配一个原子 Judge**（比如“漏转人工”归一个，“预订漏调”归一个）。问题变窄、指令变清晰之后，中小模型和大模型的差距往往会收窄很多。

日常落地可以沿用这套最稳的四步闭环：

1. **先定合格门槛再筛模型**：写好评判规则后，先按业务容忍度画好 Precision/Recall 最低合格线，不达标的模型直接淘汰；
2. **先调阈值再比高低**：切忌拿默认 `0.50` 下结论，先在交叉验证下选出贴合业务代价（$F_1$ 或 $F_\beta$）的最优阈值；
3. **要信概率就必做校准验证**：想把分数当风险概率用，先画校准曲线；套了 Platt scaling 之后要用 Brier 分数实测验证确实有改善才保留；
4. **综合算账并持续重跑**：按准确率、成本与时延三本账定选型（Randy Olson 的更广泛对比也印证：**分类和路由上决策模型性价比极高，但强依赖外部知识和长程推理的任务仍是通用 LLM 领先**）。一旦后续改过 Prompt 或业务版本，阈值与校准参数全都要重新跑一遍。

## 03 原理深潜：从概率校准、贝叶斯先验到原子 Judge 聚合

> 以下系作者结合前文评测现象，以及《Jev-like技术方案调研》《RLCD：校准决策的目标函数、约束与训练算法》（工作内部文件）整理的进阶原理笔记，非原文转载。

为什么有的模型概率极准却过不了双 80%，有的模型默认分歪得离谱、修一下却能拿高分？把背后的统计直觉和数学公式对上号，训练和接入时就能少走一大半弯路。

### 3.1 排序能力 vs 校准度：为什么“报数准”不等于“抓得准”？

先看前面实验里最反直觉的一幕：**Jev 1.13 的概率几乎贴在完美对角线上，但在双 80% 筛选里却落榜了；反倒是原始概率严重偏离的 Perplexity 27B 先过了双 80% 线，最后补一步 Platt scaling 就把概率也掰直了。**

原因在于模型输出的那一个数字 $S \in [0, 1]$，其实同时背负着两件完全不同的活：**排序力（能不能把坏轨迹排在好轨迹前面）**与**校准度（标出来的数字是不是真实出错率）**。打个比方，就像水果分拣员：排序力看的是他“能不能把烂苹果和好苹果分筐”，校准度看的是他“在筐子上贴的烂果率标签是不是童叟无欺”。一个只管对每筐苹果无脑贴上大盘平均烂果率的老实人，标签数字准得吓人，却一个烂苹果也挑不出来。

数学上，设真实失败标签为 $Y \in \{0, 1\}$，总体失败基率为 $\pi = \mathbb{E}[Y]$，模型报出分数 $S = s$ 时的真实条件失败率为 $m(s) = \Pr(Y = 1 \mid S = s)$。衡量概率总误差的 Brier 分数在总体分布上可以精确拆成三块（Murphy 分解）：

![Brier 分数的 Murphy 分解：校准误差、分辨率与不确定性](../../assets/imgs/jev/judge-evals-06.png)

- **$\mathrm{REL}$（Reliability，校准误差）**：字面报数 $S$ 与该分数桶真实失败率 $m(S)$ 差了多远；完美校准时 $\mathrm{REL} = 0$。
- **$\mathrm{RES}$（Resolution，分辨率 / 排序区分度）**：不同分数桶的真实失败率 $m(S)$ 拉开了多大差距；只会无脑报总基率 $\pi$ 的“老实模型”，$\mathrm{REL} = 0$ 但 $\mathrm{RES} = 0$，毫无分类价值。

搞清这层拆分，就看懂了事后校准的边界：**只要对所有样本的原始打分套用同一个严格递增函数 $S' = g(S)$（比如温度缩放 $T > 0$，或斜率 $a > 0$ 的 Platt scaling），样本之间的大小排队顺序压根没变。** 原先卡阈值 $\tau$ 拦出来的告警名单，跟校准后卡 $g(\tau)$ 拦出来的名单一模一样：

$$
\{S \ge \tau\} = \{g(S) \ge g(\tau)\}
$$

用大白话翻译：单调校准就像把温度计上的“摄氏度刻度”换算成“华氏度刻度”——哪杯水更烫的先后次序纹丝不动，所以 **AUROC、整条 PR 曲线以及最优 F1 分毫未变**，分辨率 $\mathrm{RES}$ 也不变，Brier 分数降下来的那部分几乎全来自消除校准误差 $\mathrm{REL}$。

这也顺手破除一个训练误区：单纯给 logits 乘一个放大系数，只是拉宽了纸面数字的跨度，根本拉不动分类排序或 PR 曲线。**自训模型的第一要务永远是先把好坏样本排开（提高 $\mathrm{RES}$），在此基础上再把概率刻度对齐（压低 $\mathrm{REL}$）。**

### 3.2 贝叶斯先验与误判代价：为什么 `0.50` 几乎总是错的？

为什么前面那么多模型死卡 `0.50` 就翻车，而 Clef Flash 会出现“预测 8%、实际错了 60%”？把 $0 \sim 1$ 的概率还原到**对数几率**（logit / log-odds）空间，答案一下子就透亮了。

记概率为 $s = \sigma(z) = \frac{1}{1 + e^{-z}}$，对应的对数几率为 $z = \operatorname{logit}(s) = \log\frac{s}{1 - s}$，默认的 `0.50` 阈值正好卡在 $z = 0$。所谓的 Platt scaling，不过是在这个空间做了一次拉伸加平移：$s_{\mathrm{cal}} = \sigma(a z + b)$，斜率 $a$ 调松紧（当 $b = 0, a = 1/T > 0$ 时就是温度缩放），截距 $b$ 管整体左右挪移。

在现实里，最常逼着截距 $b$ 发生平移的元凶叫做**贝叶斯先验基率偏移（Prior / Base-rate Shift）**。

先用大白话打个比方：**这就像把一台在“ICU 急诊科”校好阈值的危重预警仪（一半病人真有生命危险，$\pi_{\mathrm{tr}} = 50\%$），直接搬到“社区常规体检中心”（只有 2% 的人有问题，$\pi_{\mathrm{te}} = 2\%$）去用。** 哪怕仪器看化验单症状的能力一点没变（即两类样本各自的特征生成机制 $\Pr_{\mathrm{te}}(X \mid Y) = \Pr_{\mathrm{tr}}(X \mid Y)$ 完全一致），因为背景“发病底座”差了几十倍，同一张化验单在体检中心对应的真实风险也必然大幅下调。

套上贝叶斯公式两边取对数几率，这个结论干脆利落得像一条物理定律：

$$
\operatorname{logit} q_{\mathrm{te}}(x)
= \operatorname{logit} q_{\mathrm{tr}}(x) + \underbrace{\operatorname{logit}(\pi_{\mathrm{te}}) - \operatorname{logit}(\pi_{\mathrm{tr}})}_{\text{由基率变化引起的常数偏置 } b}
$$

公式后面的那一项 $\operatorname{logit}(\pi_{\mathrm{te}}) - \operatorname{logit}(\pi_{\mathrm{tr}})$ 就是基率变化直接贡献的常数偏置 $b$：只要你的线上故障率跟模型当初训练数据的故障率不一样，哪怕模型判别能力满分，它的真实对数几率也已经整体平移了 $b$。死守 `0.50` 不放，一定会造成系统性的漏报或大水漫灌式的误报（这也解释了《Jev-like技术方案调研》第 2 节看到的现象：Jev 在多个基准混在一起算 ECE 误差只有 0.047，一旦拆回各个基率不同的单个基准去算，中位 ECE 立刻反弹到 0.168）。

更进一步说：**就算模型概率已经针对你当前业务的数据集完美校准好了，默认切在 `0.50` 依然大概率不是最优解。** 因为在二元决策里还有两条硬逻辑：

1. **调阈值在数学上等价于在 logit 上加偏置**：对任意门槛 $\tau \in (0, 1)$，均有

   $$
   s \ge \tau \iff z - \operatorname{logit}(\tau) \ge 0
   $$

   把切分点定在 $\tau$，等价于先给 logit 平移 $b_\tau = -\operatorname{logit}(\tau)$ 再用 `0.50` 截断（但注意：移动切分点只改分类决策，并不等于校准了概率读数）。
2. **业务上的错判代价不对称，直接决定门槛该放哪儿**：假定判对不赔钱，误报一次（FP）代价是 $C_{\mathrm{FP}} > 0$，漏报一次（FN）代价是 $C_{\mathrm{FN}} > 0$。当模型分数 $s$ 已校准准确时，判为 Fail 的期望赔付是 $(1 - s)C_{\mathrm{FP}}$，判为 Pass 的期望赔付是 $s C_{\mathrm{FN}}$。让两边期望代价扯平，算出最小化总损失的贝叶斯最优阈值为：

   $$
   \tau^* = \frac{C_{\mathrm{FP}}}{C_{\mathrm{FP}} + C_{\mathrm{FN}}}
   $$

   用大白话理解这个分式：假如误发一条假告警只是让值班同学白扫一眼（$C_{\mathrm{FP}} = 1$），但漏掉一条线上退款漏洞要赔 9 块钱（$C_{\mathrm{FN}} = 9$），那么代进公式得出 $\tau^* = \frac{1}{1+9} = 0.10$——只要模型认为有 10% 以上的出事概率，就该立刻拉警报拦截，绝不能等到 50%！**只有误报和漏报赔的钱一模一样时，`0.50` 才恰巧是最优阈值。**

因此，世界上不存在一套写死就能通吃所有业务的万能默认阈值，留出一小批带标签业务样本在交叉验证下调阈值、验校准，永远是上线前的标准动作。

### 3.3 训练损失怎么塑造概率：为什么严格正常评分规则与 GRPO 水火不容？

如果我们自己从头训决策模型，怎么在训练阶段保证模型“老老实实报出真实条件概率 $q = \Pr(Y = 1 \mid X = x)$”？关键在于损失函数必须满足**严格正常评分规则（Strictly Proper Scoring Rules）**——大白话就是“**只有诚实报出自己心里的真实概率，长期期望罚分才最低的游戏规则**”。

固定一条输入 $x$，设真实失败概率 $q \in (0, 1)$，模型输出概率 $s = s_\theta(x) \in (0, 1)$。看最经典的两个二分类损失——Brier 平方损失 $\ell_{\mathrm{Brier}}(s, y) = (s - y)^2$ 与交叉熵损失 $\ell_{\mathrm{CE}}(s, y) = -y\log s - (1 - y)\log(1 - s)$，它们对 $s$ 求期望导数分别是：

$$
\frac{\partial}{\partial s}\mathbb{E}[\ell_{\mathrm{Brier}} \mid x] = 2(s - q), \qquad
\frac{\partial}{\partial s}\mathbb{E}[\ell_{\mathrm{CE}} \mid x] = \frac{s - q}{s(1 - s)}
$$

只要 $0 < q < 1$，两个导数都在 $s = q$ 处唯一归零（$q=0$ 或 $1$ 时贴向边界）。模型只要容量够、优化充分，最小化 Brier 或 CE 天生就会逼出真实概率 $q$。反过来，如果训练时手痒改了常见配方，最优点马上就会跑偏：

1. **标签平滑（Label Smoothing）会把概率整体往 `0.50` 挤**：把硬标签 $Y \in \{0, 1\}$ 平滑成 $\tilde{Y} = (1 - \varepsilon)Y + \frac{\varepsilon}{2}$（$0 < \varepsilon < 1$）再去跑交叉熵，期望损失的零点直接变成：

   $$
   s^* = (1 - \varepsilon)q + \frac{\varepsilon}{2}
   $$

   好端端的高风险样本（$q > 0.5$）被压扁了分数，低风险样本（$q < 0.5$）反而被平白抬高，模型变得“含糊其辞”。
2. **只认对错的 0/1 奖励会把概率轰向极端顶点**：如果强化学习时按分布 $p_1 = s, p_0 = 1 - s$ 采样动作 $A \in \{0, 1\}$，答对给 1 分、答错给 0 分（$C = \mathbf{1}[A = Y]$）且不加其他强约束，那么期望奖励对 $s$ 的导数是常数 $2q - 1$——只要 $q > 0.5$ 就死命往 `1` 推，$q < 0.5$ 就死命往 `0` 踩。这就是普通强化学习模型动不动输出 `0.999` / `0.001` 的数学根源。
3. **带校准项的 RLCD 梯度，为什么千万不能套用 GRPO 的组内标准差归一化？**：在 RLCD（如社区 eve-rlcd 实现）中，标量奖励被巧妙设计为 $r = \mathrm{sg}(C - p_A)$（$\mathrm{sg}$ 表示梯度截断）。在期望上，这个策略梯度正好等价于 Brier 损失的负梯度：

   $$
   \mathbb{E}_{A \sim p}\big[r \nabla_\theta \log p_A \mid x\big]
   = 2(q - s)\nabla_\theta s
   = -\nabla_\theta \mathbb{E}\big[(s - Y)^2 \mid x\big]
   $$

   这里有两处极容易掉进去的工程坑：
   - **有直接标签就别绕远路玩采样 RL**：二分类任务里只要手里直接有标签 $Y$（哪怕从采样对错 $C$ 和动作 $A$ 也能立刻反推出 $Y$），直接对 $(s - Y)^2$ 或交叉熵求导就能拿到零方差的精确梯度，没必要引入采样方差。
   - **照搬 GRPO 组内归一化会直接废掉校准项**：假如照抄 GRPO 对同一题采出的 $G$ 个答案做“减均值再除以标准差”。在硬标签 $y$ 下，答对给 $r = 1 - p_y$，答错给 $r = -(1 - p_y)$，合并起来就是：

   $$
   r = (1 - p_y)(2C - 1)
   $$

   问题来了：对于同一道题的这 $G$ 个采样，$1 - p_y > 0$ 是个完全相同的正因子！而标准化操作 $(r - \bar{r}) / \sigma_r$ 对任何正倍数的缩放完全免疫——**$(1 - p_y)$ 就在分子分母里被上下约掉了**！好比全班成绩统一乘以同一个正系数后再算标准分，排名纹丝不动，原本专门用来锁住校准不动点的 $-p_A$ 项凭空蒸发，训练又退化成纯 0/1 奖励，概率再次塌回 0 和 1。

### 3.4 业务卡死“双 80%”门槛时，自训阶段怎么发力？

既然事后调阈值救不了整条没及格的 PR 曲线，自训模型时就可以用上两个实用的训练思路：

#### 第一步：把“双 80%”写成约束指标盯紧验证折

设阈值为 $\tau$ 时触发告警规则 $h(x) = \mathbf{1}[s_\theta(x) \ge \tau]$，记总体真正例比例 $u = \mathbb{E}[Y h(X)]$，总体假正例比例 $v = \mathbb{E}[(1 - Y)h(X)]$，正例基率 $\pi = \mathbb{E}[Y]$（$u + v > 0, \pi > 0$）。那么业务线卡死的 $\mathrm{Precision} \ge P_0$ 和 $\mathrm{Recall} \ge R_0$ 其实就是关于 $(u, v)$ 的两条简单线性不等式：

$$
\begin{aligned}
\mathrm{Precision} = \frac{u}{u + v} \ge P_0 &\iff (1 - P_0)u \ge P_0 v,\\
\mathrm{Recall} = \frac{u}{\pi} \ge R_0 &\iff u \ge R_0 \pi
\end{aligned}
$$

写出来就能一眼避开两个常见误解：
1. “Precision 和 Recall 都达到 80%”是全局排序约束，**绝不是把阈值 $\tau$ 设成 `0.80`**；
2. 挑 Checkpoint 和做困难样本挖掘（Hard Negative / Hard Positive Mining）时，别只盯着全盘平均 Brier 或 NLL 下降，**直接在验证折上追踪受约束工作点指标**（比如“在满足 $\mathrm{Precision} \ge 80\%$ 的所有阈值里，Recall 最高能到多少”）。

#### 第二步：用 Schervish 阈值加权损失把小模型的有限算力保在刀刃上

如果小尺寸模型容量有限，而你已经明确下游大概就在某个 $\tau \in (0, 1)$ 附近切一刀（或划了一条 `0.20～0.80` 的灰区），能不能让损失函数重点打磨 $\tau$ 附近的分辨与校准，又不破坏“如实报概率”的根基？先看一个**反面陷阱**和**正确做法**：

- **陷阱写法（拿 sigmoid 硬替阶跃函数做代价敏感损失）**：有人直接把阈值为 $\tau$ 的硬截断代换为软决策 $d(s) = \sigma\!\left(\frac{s - \tau}{\delta}\right)$（$\delta > 0$ 为平滑宽度），写成：

  $$
  \ell_{\mathrm{naive}}(s, y) = \tau(1 - y)d(s) + (1 - \tau)y\big(1 - d(s)\big)
  $$

  对条件期望一求导就露馅了：

  $$
  \frac{\partial}{\partial s}\mathbb{E}[\ell_{\mathrm{naive}} \mid x]
  = \frac{\tau - q}{\delta}\,\sigma'\!\left(\frac{s - \tau}{\delta}\right)
  $$

  导数正负只看真概率 $q$ 在 $\tau$ 的左边还是右边！只要 $q > \tau$ 就一路把 $s$ 往 `1` 推，$q < \tau$ 就往 `0` 推——不仅没在阈值附近校准，反而把灰区样本强行推离边界。
- **正确写法（Schervish 阈值积分加权）**：Schervish 定理说明任何正常评分规则都能写成不同阈值 $t \in [0, 1]$ 上代价敏感损失的加权积分（标准 Brier 对应均匀权重 $w(t)=2$，CE 对应 $w(t)=\frac{1}{t(1-t)}$）。我们在 $[0, 1]$ 上构造一个非负可积权重密度 $w(t)$——比如在重点关照的阈值 $\tau$ 附近放一个窄高斯峰，底盘垫一点正基础权重 $\varepsilon_0 > 0$（等价于保留底部的 Brier 项）：

  $$
  \ell_w(s, 1) = \int_s^1 (1 - t)w(t)\,dt, \qquad
  \ell_w(s, 0) = \int_0^s t\,w(t)\,dt
  $$

  由微积分基本定理，它对概率 $s$ 和 logit $z$ 的条件期望梯度极其干净：

  $$
  \begin{aligned}
  \frac{\partial}{\partial s}\mathbb{E}[\ell_w \mid x] &= (s - q)\,w(s),\\
  \frac{\partial}{\partial z}\mathbb{E}[\ell_w \mid x] &= (s - q)\,w(s)\,s(1 - s)
  \end{aligned}
  $$

  因为 $w(s) > 0$，**理论上每一点的最优解依然稳稳停在真实概率 $s = q$ 上**，同时模型在阈值 $\tau$ 附近得到的校准梯度权重明显更大。
- **务必清醒的代价（有限容量下的“误差搬家”）**：前面“每一点都能停在 $s = q$”的前提是样本之间参数互不打架。但小模型参数总是共享、容量总是有限的，把拟合预算集中倾泻到阈值 $\tau$ 附近，相当于**拆东墙补西墙——非关键区域的误差会跟着涨起来**。
  举个极简算例：两组等权样本真概率分别为 $q_1 = 0.80$ 和 $q_2 = 0.60$，由于模型表达受限只能输出耦合值 $s_1 = \theta, s_2 = \theta - 0.30$（$\theta \in [0.30, 1]$）：
  1. 用均匀权重的标准 Brier 训，最优解折中在 $\theta = 0.85$（两组分别报 0.85 和 0.55，各差 0.05），全局 $\mathrm{REL} = 0.0025$；
  2. 改用集中在 $\tau = 0.80$ 附近的权重 $w(t) = 0.2 + \varphi_{0.80, 0.03}(t)$（$\varphi_{\mu, \sigma}$ 为正态密度），最优解会滑到 $\theta \approx 0.8015$——第一组在 `0.80` 边界被精修到了 `0.8015`，但第二组被拉偏到 `0.5015`（偏差逼近 0.10），整体 $\mathrm{REL}$ 反而翻倍到约 `0.0049`。所以 Schervish 加权适合在重点工作点周边精雕细琢，最终能否抬高验证集受约束的 P/R 仍要拿实验说话。

### 3.5 原子 Judge 拆分、共享前缀与二次聚合：别让概率组合掉进坑里

最后回到我们在第 02 节最后留下的那条实战原则：**不要让一个大裁判去抓全部错，而要拆成一组职责单一的原子 Judge。** 这件事放到 Jev 这类单次前向决策模型上，直接牵出三个极有工程价值的设计与陷阱。

#### 1. 为什么要拆成 $M$ 个原子 Judge？给“不打草稿纸”的模型减负

前面测的“找出 20 轮公寓租赁轨迹里的任何错误”，等于逼着一个不写 CoT 思维链、只做单次前向计算的模型，在固定网络层数里一口气做完“跨 20 轮检索对话状态 → 核对五六条规则 → 脑内求逻辑 OR 汇总”。一旦拆成 $M$ 道职责极其单一的原子是非题——例如 $q_1$“用户明确要求转人工时是否未调用转接接口”、$q_2$“双方确认看房时间后是否未调用预订工具”、$q_3$“Agent 报价是否与房源表冲突”——每道题都只盯局部事实，不仅小模型一判一个准，线上归因和人工复核也直接带出了明确错因。

#### 2. 拆成 $M$ 道题之后，怎么不让 API 账单翻 $M$ 倍？

如果傻傻发 $M$ 次独立 HTTP 请求，同一段长轨迹就要被重复算 $M$ 遍，成本直接乘以 $M$。

而在支持**共享前缀预填充（Shared State Prefill）与题间隔离读出**的决策模型架构中（参考内部文件《Jev-like技术方案调研》第 3 节 QwenJev-Lite 方案），长对话历史只需在前向时 Prefill 一次生成共享 KV 缓存，随后把 $M$ 个短小的问题头作为互不干扰的并行分支接在后面同时读出。记长轨迹 Prefill 开销为 $C_{\mathrm{pre}}$，单道短问题增量开销为 $C_q$，两种成本差距一目了然：

$$
C_{\mathrm{shared}} \approx C_{\mathrm{pre}} + M C_q, \qquad
C_{\mathrm{separate}} \approx M(C_{\mathrm{pre}} + C_q)
$$

只要轨迹长而问题短（$C_{\mathrm{pre}} \gg M C_q$），一次前向问完 $M$ 个原子 Judge 的成本，几乎跟只问 1 题没什么差别。

#### 3. 大坑警告：“题间隔离”不等于“现实中的错误相互独立”！

拿到 $M$ 个原子概率 $p_1, p_2, \dots, p_M$（其中 $p_j \approx \Pr(E_j \mid X)$ 代表第 $j$ 种错误出现的概率）后，如果老板或下游系统要看一个总指标：“**这条轨迹至少犯了一种错误的总体失败概率 $P_{\mathrm{any}} = \Pr\!\left(\bigcup_{j=1}^M E_j \;\middle|\; X\right)$ 是多少？**”

十个人里有九个会条件反射写出独立并集公式：$1 - \prod_{j=1}^M (1 - p_j)$。**但大错特错！**

用大白话解释原因：**模型注意力掩码上的“题间隔离”，只是挡住了第 1 题的考卷不让它偷看第 2 题的题干；但在现实业务里，这 $M$ 道题查的可是同一条对话轨迹！** 只要 Agent 一开始就误解了用户的核心诉求，它极可能在同一条轨迹里既报假价格又漏调工具——两类错误高度正相关甚至同生共死。

当各失效事件的相关性未知时，光靠边缘概率 $p_j$，数学上能框出来的真实范围其实宽得吓人（Fréchet–Boole 上下界）：

$$
\max_{1 \le j \le M} p_j
\;\le\; \Pr\!\left(\bigcup_{j=1}^M E_j \;\middle|\; X\right)
\;\le\; \min\!\left(1, \sum_{j=1}^M p_j\right)
$$

拿两个原子 Judge 算笔简单账就懂了：假设某类轨迹上 $p_1 = p_2 = 0.30$：
- 如果两类错误总是由同一个根因同时触发（完全重合），真实“至少错一项”的概率只是 $\max(0.30, 0.30) = \mathbf{0.30}$；
- 如果两类错误在统计上刚好真正独立，才是 $1 - (1 - 0.30)^2 = \mathbf{0.51}$；
- 如果两类错误此消彼长绝不同时发生（互斥），则是 $0.30 + 0.30 = \mathbf{0.60}$。

**所以，“每个原子 Judge 各自校准准了”，绝不代表拿公式一乘一减拼出来的总概率也准！** 工程上靠谱的消费方式只有两条路：

- **路径一（只做规则告警，不硬凑总概率）**：给每条原子规则 $j$ 分别卡好各自的阈值 $\tau_j$，线上只要任意一条 $p_j \ge \tau_j$ 就直接报警并带出具体错因标签，最后统一在轨迹级测试集上验总体告警的 Precision 和 Recall。
- **路径二（既要子项诊断，又要准的整轨总风险分）**：把 $M$ 个原子输出喂给一个超轻量的“**二次聚合校准器**”。

#### 4. 怎么把 $M$ 个原子分数聚合成靠谱的总风险概率？

动手前先明确一点：**这 $M$ 个原子 Judge 是 $M$ 个独立的“是/否（Sigmoid）”开关，不是互斥“多选一（Softmax）”**。每道题的 $p_j$ 只和自己的 $1 - p_j$ 相加等于 `1`，一条翻车轨迹可以同时触发好几项错误，所以 $p_1 + \dots + p_M$ 完全可能大于 `1`。

要做第二层监督聚合（用整轨真值标签 $Y \in \{0, 1\}$ 拟合汇总模型），常见有从简到繁两种做法：

**做法 A（极简基线）：先用手工公式拍扁成 1 个数 $r$，再做 1 维 Platt scaling**

当带轨迹级真值标签的校准样本少得可怜（只有几十上百条）、不敢拟合多参数模型时，可以先退一步：
1. 先拿启发式公式（如取最大值 $r = \max_j p_j$，或借用乘积形式）把 $M$ 个数压成一个候选总分 $r \in (0, 1)$：

$$
r = 1 - \prod_{j=1}^M (1 - p_j)
$$

（按前例 $p_1 = p_2 = 0.30$ 算出“都不错”的乘积 $0.70 \times 0.70 = 0.49$，再用 1 减得候选分 $r = 0.51$。）
2. **再套 1 维刻度校准**：把 $r$ 当唯一输入，用轨迹真值标签 $Y$ 拟合两个参数 $(a, b)$：$\widehat{P}_{\mathrm{any}} = \sigma\!\big(a\,\operatorname{logit}(r) + b\big)$。只要标注集显示“报出 $0.51$ 的轨迹其实只有 30% 真错”，校准层就会自动把输出压回 $0.30$ 附近。

**为什么说做法 A 只是个妥协基线？** 因为它有两处硬伤：一是在拍扁成单个 $r$ 时把组合结构扔光了（“两项并发各 0.30”跟“只有一项 0.51 另一项 0”算出的结果无法区分）；二是当 $a > 0$ 时它是严格递增变换，**所有样本的高低排序已经被第一步的手工公式死死锁死，整条 PR 曲线纹丝不动**，只修正了显示的概率数字。

**做法 B（更推荐的标准做法）：保留全部 $M$ 个子项对数几率，用多变量逻辑回归同时学“权重”和“校准”**

既然先拍扁会扔掉信息，不如跳过手工汇总公式，直接把 $M$ 个原子 Judge 的对数几率 $z_j = \operatorname{logit}(p_j)$ 拼成 $M$ 维特征向量，在轨迹标签 $Y$ 上拟合带正则化的多变量逻辑回归：

$$
\widehat{P}_{\mathrm{any}} = \sigma\!\left(b + \sum_{j=1}^M \beta_j z_j\right)
$$

保留全部 $M$ 个特征交给二层聚合器，立刻多出三大实打实的好处：
- **分得清“单项存疑”和“多项同时报警”**：比如两条轨迹得分分别是 $(0.60, 0.10)$ 和 $(0.60, 0.60)$。取 $\max$ 会把两条都看成 `0.60`，而多变量回归能利用第二项信号给后者打出显著更高的综合风险；
- **自动给冗余和噪声规则调权重**：如果第 1 题和第 2 题总是同报同错、高度重合，回归会自动压低它们的系数避免重复计分；判别准的原子裁判权重 $\beta_j$ 自然放大，纯噪声规则权重会向 0 收缩；
- **真正重学了排序，能把整条 PR 曲线往上抬**：因为不同子项拿到了从真实业务数据学出来的话语权（样本够多还能补 $z_j z_k$ 交叉项捕捉共现规律），轨迹的综合风险排序被重新优化了一轮。

不过无论用做法 A 还是做法 B，**一层原子特征的覆盖面永远决定整个系统上限**：二层聚合器眼里只有那 $M$ 个分数，根本看不见原始对话长啥样。一旦线上冒出一类没覆盖进现有 $M$ 道题的新故障，两条同样分数却一成一败的轨迹在这里无解——此时唯有回到错误分析闭环，把漏网的失效模式补写成第 $M+1$ 个原子 Judge。

## 04 写在最后

回过头看，决策模型给自动化评测带来的最本质变化，是让我们重新拿回了**一个连续、可拆解、可调节的风险信号**。

以前拿生成式 LLM 做裁判，模型黑盒吐出一个 `Pass` 或 `Fail`，把“正负样本分不分得开”“报出的概率准不准”和“业务阈值切在哪”三件事死死焊在一起。现在它们终于能拆开单练：分辨力行不行看 PR 曲线，数字诚不诚实看校准曲线和 Platt scaling，业务上更怕误杀还是漏放靠移动阈值拍板。很多时候便宜模型并非不能用，只是必须老老实实过一遍交叉验证调阈值与校准这几道基本功，才能稳稳推上生产。

最后留下两个仍在演进、目前还没有标准自动解的开放问题：

1. **带思考的决策模型（Thinking Decision Model）该如何平衡成本与上限**：单次前向决策模型省钱快跑，靠的是砍掉思维链。但如果 20 轮对话里的错误是“第 3 轮承诺的折扣到第 18 轮算总账时漏扣了”，或者需要先算清楚两个日期相差几天再判违约，没有草稿纸的纯前向小模型很难算对。这类需要多步算术或长距跨轮状态的场景，当前要么靠前置业务代码把中间结果先算好喂进输入，要么还得退回带推理链的模型；未来怎么设计既快又会局部推演的决策模型，仍然是个值得盯紧的方向。
2. **线上数据分布漂移时，怎么自动守住校准和阈值**：无论是最佳阈值还是 Platt scaling 的斜率截距，都长在当前这批样本的错题比例和分布上。等线上 Agent 修掉几个高频 bug、或者升级一版 Prompt，基率和分布一变，原来锁死的参数就会跟着偏移。如何低成本在生产流量上及时嗅探到分数漂移，并用最少的人工补标完成周期性重校准，目前依然需要工程机制去持续摸索。
