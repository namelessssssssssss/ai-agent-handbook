# 运行篇导读

在开发机上跑通一个 Agent，和把它放到生产环境里服务成千上万个用户，面临的根本不是同一个问题。在本地调试时，进程挂了重新跑一遍就行，状态全塞在内存里也无所谓；可一旦进入线上并发，任何一次实例重启、连接断开或超时重试，都会立刻演变成任务丢失、重复下单、账目对不上，甚至完全查不清刚才到底发生了什么。

运行篇解决的正是「从实验室 Demo 跨进生产系统」这一步的工程复杂度，核心围绕两条递进主线展开：**先把单个 Agent 跑稳（运行的地基），再让多个 Agent 有序干活（运行的秩序）**。

| 主线 | 对应章节 | 要解决的真实问题 | 核心工程机制 |
| --- | --- | --- | --- |
| 运行的地基：让单个 Agent 跑稳 | 第 07 章 | 算力和工具在哪跑才安全、不丢进度 | Sandbox 隔离环境、Runtime 生命周期调度、休眠恢复、围栏防脑裂、快照与分叉 |
|  | 第 08 章 | 任务进度、文件成果和记忆知识存在哪 | Event Log、Checkpoint、分层工作区与 Artifact Store、长期记忆、RAG 与本体 |
|  | 第 09 章 | 流量、账单、凭证和工具调用怎么收口 | AI Gateway（LLM / MCP / Agent 三类治理）、原子预算预留、异步审批、智能路由 |
| 运行的秩序：让多 Agent 协同干活 | 第 10 章 | 跨几小时甚至几天的任务怎么调度与验收 | 同步与异步边界、任务完成语义分层、任务队列与背压、定时触发、DAG 工作流 |
|  | 第 11 章 | 一群异构 Agent 怎么拆活、交接和汇总 | 异构接入适配、主管/对等/分层拓扑、最小充分共享视图、停止条件与入/出站权限 |
|  | 第 12 章 | 跨进程、跨节点的通信断了怎么接回来 | 人机/能力/协作/内构四个通信面、S1–S4 四档交互语义、轻量会话通道与手脑分离 |

**第一条主线（第 07—09 章）是运行的地基**：
- **第 07 章** 讲执行环境：为什么不能把 Agent 丢进普通无状态容器里裸奔，CPU 一闲就回收、休眠醒来凭证失效、旧实例假死引发双写脑裂，以及怎么用 Runtime + Sandbox 解决；
- **第 08 章** 讲状态与数据落盘：任务事实、工作区文件、长期记忆、外部知识库、业务本体这几类数据一致性要求完全不同，混存必翻车，怎么按对象分层存储并统一治理；
- **第 09 章** 讲统一流量入口：把分散的 Key、额度、审批、模型降级和工具鉴权收口到 AI Gateway，并展示 HiRoute 如何靠阶段路由与真实回放把主力模型额度省在刀刃上。

**第二条主线（第 10—12 章）是运行的秩序**：
- **第 10 章** 讲长程异步与自动化：彻底拆开「进程退出」和「业务成功」，讲清任务状态机、外置调度、人工审批挂起以及防刷爆账单的止损边界；
- **第 11 章** 讲 Multi-Agent 编排：不盲目建复杂团队，讲清什么场景真该拆队、异构 Coding Agent 和本地助手怎么安全接入、交接清单怎么写才不会互相污染；
- **第 12 章** 讲分布式通信：用「四个通信面 × 四档交互语义」的选型地图，把五花八门的协议（MCP、A2A、AG-UI、RocketMQ LiteTopic）还原为「连接断了状态靠谁兜底」的工程判断。

两段主线是严格的递进关系：单个 Agent 的状态和环境还没稳，强行上多 Agent 只会把不确定性乘以 N 倍。如果你正准备把第一个 Agent 推上线，优先精读第 07—09 章；如果你的单兵 Agent 已经跑稳，正在向无人值守、异步长任务或多智能体协作扩展，可以直接聚焦第 10—12 章。
