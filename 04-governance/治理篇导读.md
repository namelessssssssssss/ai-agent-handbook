# 治理篇导读

把 Agent 塞进测试环境跑通一个 Demo 很容易，但真放到线上交给真实用户和自动化任务去跑，工程团队往往会立刻撞上四堵墙：

1. **出了错不知道卡在哪一步**：接口明明返回了成功状态，业务却没办成——到底是认知大脑 `Model` 推理跑偏、知识检索没召回、工具假装成功、隔离执行空间 `Sandbox` 内存爆了，还是长任务调度宿主 `Runtime` 与推理引擎批处理互相拖慢？
2. **不敢把真权限交出去**：一封外部邮件里夹着几句隐蔽指令、一个第三方 MCP 工具描述里藏着“顺便外发日志”的小动作，或者代码里硬编码了一把万能密钥，就可能把高权限 Agent 变成替攻击者干脏活的“困惑代理人”。
3. **资产散落一地，改一处不知道炸几处**：同一份 Prompt 被复制进十几个仓库、网上拉来的 Skill 直接进生产目录、MCP Server 改个字段不知道哪个上游 Agent 会挂、新老版本混跑却无法回放现场。
4. **改完不敢上线，上线才见真问题**：模型输出带概率性，不像人类员工那样有执业资格、行业规程和失败惩罚；如何在**不碰生产数据、不发真实扣款**的前提下，提前把暴躁用户、接口超时和响应丢失演练一遍？

**治理不是给系统生硬套枷锁，而是让跑起来的 Agent 变得可信**。更重要的是，治理沉淀下来的全链路 Trace、权限审计证据、不可变资产版本和仿真基线，正是下一篇[调优篇](../05-optimization/00%20调优篇导读/调优篇导读.md)做根因定位和效果评测时唯一能信的事实输入——没有治理底座，调优只能靠猜。

| 章节 | 解决的痛点 | 核心机制 |
| --- | --- | --- |
| [第 13 章　Agent 的可观测性](<./第 13 章　Agent 的可观测性.md>) | 看不清 Agent 到底干了什么，慢和贵找不到责任层 | 统一应用埋点、Hook/Daemon 与 eBPF 三路采集；用 Session / Trace / Span 还原因果链；穿透 AI 网关、推理引擎并发视图与沙箱副作用；形成可执行审计证据链 |
| [第 14 章　Agent 安全](<./第 14 章　Agent 安全.md>) | 怕被提示词注入劫持，更怕 Agent 自己越权闯祸 | 覆盖应用、模型、数据、身份与网络沙箱的纵深防御；以“困惑代理人”防御、Token Exchange 最小权限收权、会话级微虚拟机隔离和默认拒绝出站守住爆炸半径 |
| [第 15 章　AI 资产的发现与管理](<./第 15 章　AI 资产的发现与管理.md>) | Prompt/Skill/MCP/Agent 散落失控，动态加载会污染上下文 | 构建统一资产注册中心（Registry）与准入流水线；稳态 Agent 靠声明式锁定清单保确定性，动态 Agent 靠 ARD/RAD 按任务受控发现；通过 Context Manifest 保证过程可回放 |
| [第 16 章　Agent 行为生成与质量验证](<./第 16 章　Agent 行为生成与质量验证.md>) | 上线前无法充分演练多轮博弈与异常故障 | 用可控的用户模拟器与环境模拟器包裹被测系统（SUT）；明确 Spec → Manifest → Run → Result 证据契约；把“执行完毕”和“评估通过”“允许发布”严格拆开 |

## 阅读建议

*   **第 13 章是整篇的共同地基**：没有统一口径的 Trace 和指标，安全事件查不到源头步骤，资产下线找不到受影响任务，上线前仿真也没法跟线上真实轨迹对齐。建议所有读者先从第 13 章入手。
*   **按当前最痛的问题选读后三章**：
    *   急着兜住线上稳定性、防数据泄露和越权操作：读完第 13 章后直接看第 14 章。
    *   团队开始多人共用 Prompt、Skill、MCP 和协作 Agent，版本管理已经一团乱：直接看第 15 章。
    *   准备搭建上线前回归门禁，系统验证多轮对话、故障恢复与边界行为：重点读第 16 章。
